- `v1.8.2`：**RAID 阵列和故障硬盘标记。**（1）**硬盘状态：**每个存储条目都有一个状态——*正常*、*故障*或*离线*——以及可选的备注，因此坏掉的硬盘会被保留而不是删除（`StorageInfo.status`/`statusNote`，仅在不正常时写入）。（2）**RAID 阵列：**设备编辑器新增的 *RAID 阵列*区域用设备的硬盘组建阵列（名称、级别——RAID 0/1/5/6/10、RAID-Z1/Z2/Z3、JBOD、其他——以及成员 chip；一块硬盘最多属于一个阵列），保存为新的可选设备字段 `storageArrays`，带稳定 id。设备详情显示每个阵列的级别、硬盘数和健康状况：故障成员数在级别的容错范围内时为*降级*，超出时为*已失效*。（3）**数据集：**数据集可以链接到整个阵列（`DataSetStorageLink.arrayIds`）；一个阵列无论跨多少块硬盘都只算一份副本。编辑页、分组列表（*按存储*为每个阵列一组）和拓扑（每个阵列一个存储框）显示设备的阵列和不属于任何阵列的硬盘；仍指定阵列成员的链接保持可见。故障或离线硬盘上、或已失效阵列上的副本仍会列出，但不可用：副本数显示为"n 份副本 · k 份不可用"，拓扑徽章为 `×可用数/n`，这些副本变灰并加删除线。保存设备时，加入了阵列的硬盘的数据集链接会移到该阵列，指向已移除阵列的链接会被丢弃。本地 API 和 Markdown 导出包含这些新字段。所有新键都是可选且只做增量添加；旧构建通过 `extraJson` 保留它们（它们把阵列的硬盘显示为普通槽，且不计入阵列副本）。版本统一为 `1.8.2+56` / MSIX `1.8.2.0` / 安装程序 `1.8.2`。
- `v1.8.3`：**更清晰的服务拓扑连线。**在一个真实的 homelab 中，1.8.2 的拓扑存在三个问题：几个服务的边挤在同一条竖线上，端口芯片与其服务错开一行，域名被推到分组框下方。（1）**相连节点对齐：**交叉消减扫描之后，布局按分层绘图的方式分配 y 坐标，即取邻居中位数，再用相邻违例合并算法放置，各层顺序不变。端口芯片因此与其服务齐平，服务和它的芯片作为一个整体移动。分组框放好后，框外节点（域名）也移到与它相连的节点旁边。（2）**每条边有自己的轨道：**路由之后，共用一个列间通道的竖段按减少交叉的顺序排列，彼此相隔 8 px。轨道放不下的通道，通过对画布做一次保序拉伸来加宽（libavoid 式的错开加上 ELK 式的槽位分配）。竖段共线对路由器几乎不再有代价，水平共线仍有代价，偶尔剩下的水平重合会被移开。（3）同一侧的锚点均匀分布、不再截断；几乎水平的边被完全拉平；卡片列中的芯片在列间通道里拐弯；从背面进入节点会受罚；拐弯画成圆角。在 homelab 复刻上，分组时交叉从 22 降到 3，共线长度从 82 px 降到 0。61 节点的测试图布局耗时约 1.0 s / 0.3 s，此前为 4.6 s / 0.6 s。新增按需运行的 `test/service_topology_preview_test.dart`（`TOPOLOGY_PREVIEW=<目录>`），把每个样例渲染为 PNG 并输出指标，便于肉眼检查布局改动；样例移到 `test/support/topology_fixtures.dart`。数据格式不变。版本统一为 `1.8.3+57` / MSIX `1.8.3.0` / 安装器 `1.8.3`。
