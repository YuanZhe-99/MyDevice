# 版本历史

MyDevice!!!!! 的逐发布摘要。改变行为前理解*为何*存在有用——几个条目记录否则看起来像怪癖的刻意安全修复。

## 发布

- `v0.1.0`：初始设备清单、网络、数据集、地图、在线搜索、预设、原始 WebDAV 同步、备份、ZIP 导入/导出、四语言本地化、自定义存储路径。
- `v0.1.1`：商店/full 风格、CI/CD、平台命名/图标、macOS 网络客户端权利、隐私/README 更新。
- `v0.1.2`：带基线快照和冲突对话框的逐记录三方 WebDAV 合并。
- `v0.1.3`：同步审计、设备引用级联删除、网络备注 l10n/UI 改进、版本位置文档。
- `v0.1.4`：原子同步写、逐文件错误、并发保存检测、自动同步 UI 回调、更安全基础保存。
- `v0.2.0`：硬编码 UI 字符串和语言区域感知日期格式的广泛 i18n 清理。
- `v0.2.1`：供 LLM 个性化 的 Markdown 导出。
- `v0.3.0`：本地 API 服务器、系统托盘、启动时启动、桌面设置、macOS 平台变更。
- `v0.3.1`：Windows ARM64 CI 修复，无应用版本 bump。
- `v0.3.2`：仅引用图像同步和改进同步错误/警告报告。
- `v0.3.3`：周期自动同步、存储层保存通知、自动同步 UI 刷新、未知字段保留。
- `v0.4.0`：设备生命周期和财务跟踪、汇率支持、财务总览、退役/出售清理、Markdown/详情财务输出。
- `v0.4.1`：带资产分布和日志每日成本历史/未来趋势图的财务总览分析页；自定义图像和类别回退的统一圆形设备头像渲染。
- `v0.5.0`：服务/端点/端口/路由备注的手动服务标签、多跳访问路径、Docker Compose 备注/复制、建议端口冲突、服务模板、服务同步/备份/ZIP 导入导出和本地 API 服务统计。
- `v0.5.1`：服务拓扑总览、分组访问路由、快速访问路由创建、共享 VPS/域映射的 FRP/端口转发远程入口可视化。
- `v0.5.2`：交互式服务拓扑节点、右侧公共/VPS 布局、真实拓扑图标、LAN/VPN/公共访问车道和显式 FRP 服务-on-VPS 关系。
- `v0.5.3`：服务拓扑全屏选择/移动模式、被动总览预览、经 `extraJson.publicTargets` 的分组多目标路由、隐藏/生成路由名和修正 FRP 路径语义使控制端口留在公共访问路径外。
- `v0.5.4`：服务拓扑移除小主页预览、使直接/VPN 和 VPS 分支在源端点后平行、添加不改变系统方向的应用内 90 度拓扑旋转，并添加 PNG 导出/分享。
- `v0.5.5`：服务拓扑切换语义分层布局带路由/源车道、固定本地/远程/公共列和正交捆绑边，使密集图保持本地服务与远程 VPS 暴露路径分离。
- `v0.5.6`：Markdown 导出现在含服务数据带服务端点、路由、跳、Docker Compose 备注和分组公共目标；服务拓扑保持同设备公共代理服务本地并用语义行分组减少路由族混合。

- `v0.5.12`：服务拓扑经推迟并缓存全屏布局工作、A* 路由前先试快速净空正交路由、复用障碍派生路由轨道打开更快。

- `v1.3.1`：修复自定义存储路径迁移。更改存储文件夹先前移动四个数据文件，加只走**顶层**文件的手工 `backups/` 和 `images/` 副本——因此 `backups/blobs/` 被留下且每个恢复备份静默丢失其图像——且那些副本只在目标目录尚不存在时运行。`.sync_base/` 和 `webdav_config.json` 完全被漏掉。最坏后果是静默的：无 `.sync_base/` 下次同步无基线快照，因此其他设备已删的记录读作"本地新"并被重新上传，跨每台设备复活删除；丢 `webdav_config.json` 也完全停止同步。迁移现在移动**整个**存储文件夹，除必须留在原位的 `storage_config.json`（它持有路径本身）——因此未来发布添加的数据文件无需代码变更即迁移。既有目标文件仍胜出，其源副本现在原地留下而非丢弃。共享逻辑住在 `myapps_data` `v1.0.1` 的 `migrateStorageContents`，由八个测试覆盖。版本统一为 `1.3.1+37` / MSIX `1.3.1.0` / 安装器 `1.3.1`。
- `v1.4.0`：修复在线设备搜索并刷新捆绑模板目录。**移除 GSMArena**：它对每个请求都返回以 *HTTP 200* 承载的 Cloudflare Turnstile 验证页，因此旧的状态码检查通过，随后行匹配模式失配，`search()` 返回 `[]`——与「没有这台设备」无法区分。纯 HTTP 客户端无法通过该验证。**Notebookcheck 一直可达，却被我们自己的过滤器废掉**：它把标准设备页命名为 `<name> - Reviews and Specs`，而文章过滤器丢弃一切匹配 `review` 的结果，于是 `Galaxy Z Fold8` 和 `Z Fold8 Ultra` 被丢掉，标题较短的旧款 `Z Fold7` 反而留下——过滤器恰好删掉了最新设备。它的详情页还带有完整规格表（Processor/Memory/Display/Storage/Battery/OS/Released），此前从未被读取，只取了 JSON-LD 图片，因此内存、存储、电池、系统和发布日期从该数据源根本没有到达用户。**PhoneDB** 接替 GSMArena 承担手机覆盖，并加了相关性闸门：它的 `filter=`/`model=` 参数被忽略（只有 `search_exp` 的 POST 才真正搜索），而对未收录的型号它会退化为宽松匹配，返回约 120 台无关手机。`search()` 现在返回 `DeviceSearchResponse`，为每个数据源带一个 `DeviceSearchStatus`（`ok`/`blocked`/`unreachable`/`markupChanged`），使机器人验证墙、服务中断和页面结构变化不再一律显示为「未找到结果」；零匹配查询仍判定为 `ok`，通过 `isNotebookcheckSearchPage`/`isPhonedbResultsPage` 识别，因此新信号不会对每台未收录设备虚报警。解析逻辑移入不涉及网络的 `device_search_parsers.dart`，由基于固定样本的测试覆盖；`stripHtml` 现在**解码**实体而非删除（`12&nbsp;GB` 过去会塌缩成 `12GB`）；`tool/check_sources.dart` 用一条命令报告数据源健康状况。模板方面：`device_templates.json` 自 `v0.1.0` 起未曾改动，本次新增 19 台设备（iPhone 17 全系、Galaxy S26 全系、Z Fold7/Fold8/Fold8 Ultra、Z Flip7、Pixel 10 Pro Fold、Xiaomi 17 Pro/Pro Max、Tab S11 Ultra、M5 MacBook），所有规格均从实时数据源抓取而非凭记忆填写。修复四个模板缺陷：`toDevice` 硬编码 `storage.first`，导致多容量模板永远塌缩为最小容量；14 个 VPS 模板对象形态 `cpu` 的详细信息在解析期即被丢弃且无法通过预设查找找回；选择器只搜索 `name`，尽管其列表项显示品牌/CPU/内存；`validate_json.dart` 只检查文件能否解析——现在会检查字段、类型、类别枚举、重复项与排序顺序，并立即查出四个此前无人知晓的重复预设条目。`PRIVACY_POLICY.md` 与应用内隐私页在本次工作之前就已实质失实（声称「不进行其他网络通信」，而应用早已连接 GSMArena、Notebookcheck 和 Startpage），已在四种语言中更正。版本统一为 `1.4.0+38` / MSIX `1.4.0.0` / 安装器 `1.4.0`。
