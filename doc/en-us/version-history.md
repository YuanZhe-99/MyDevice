# Version history

Release-by-release summary of MyDevice!!!!!. Useful for understanding *why* a behavior exists before
changing it — several entries record deliberate safety fixes that look like quirks otherwise.

- `v1.2.2`: Backup overhaul — backup format v2 stores images once in a content-addressed `backups/blobs/` store shared by all backups with reference-counted GC (a blob is deleted only when no remaining backup references it; legacy inline-image bundles stay restorable), bundle writes are atomic and corrupt bundles are flagged in the history (restore disabled) without suppressing the daily auto-backup retry, restore now validates module JSON via the model parsers and sanitizes image names before writing, restoring a backup reloads open pages, disables WebDAV auto-sync when sync is configured and offers an explicit force upload of the restored data (preventing restored-old data from propagating deletions to other devices), auto-backup also runs from the 15-minute periodic timer with a re-entrancy guard, backup failures show a snackbar, the ZIP import "flat files under images/" allowlist check was fixed (the old basename comparison was always true and admitted nested entries), backup UI text/CJK terminology was standardized across MyAnime/MyDay/MyDevice, and versions are unified to `1.2.2+34` / MSIX `1.2.2.0` / installer `1.2.2`.

- `v1.3.0`: Shared `myapps_data` package extraction — WebDAV sync, backup/restore, ZIP transfer, and auto-sync scheduling now come from a shared package embedded as a git submodule at `packages/myapps_data`, which MyAnime, MyDay, and MyDevice all build on; the services became thin facades so all 59 existing tests pass unmodified. MyDevice-specific behavior deliberately stayed app-side: `mergeAssignments` (composite key, no timestamps) and the synthetic `images` backup module, now an engine constructor knob. Two intentional behavior changes: a ZIP containing a path-traversal entry is rejected outright instead of having that entry skipped and the rest imported, and resume cancels a pending save-debounce before syncing (unifying the three apps; the in-flight guard already made the difference unobservable). Versions unified to `1.3.0+36` / MSIX `1.3.0.0` / installer `1.3.0`.
- `v1.3.1`: Fixed the custom storage-path migration. Changing the storage folder previously moved the four data files, plus hand-rolled copies of `backups/` and `images/` that only walked **top-level** files — so `backups/blobs/` was left behind and every restored backup silently lost its images — and those copies only ran when the destination directory did not already exist. `.sync_base/` and `webdav_config.json` were missed entirely. The worst consequence was silent: without `.sync_base/` the next sync has no base snapshot, so records other devices had deleted read as "new locally" and were re-uploaded, resurrecting deletions across every device; losing `webdav_config.json` also stopped sync entirely. Migration now moves the **entire** storage folder except `storage_config.json` (which must stay put — it holds the path itself), so a data file added in a future release migrates with no code change. Existing destination files still win, and their source copies are now left in place rather than discarded. Shared logic lives in `myapps_data` `v1.0.1` as `migrateStorageContents`, covered by eight tests. Versions unified to `1.3.1+37` / MSIX `1.3.1.0` / installer `1.3.1`.
- `v1.4.0`: Online device search repaired and the bundled template catalog refreshed. **GSMArena was removed**: it answers every request with a Cloudflare Turnstile challenge served as *HTTP 200*, so the old status-code check passed, the row pattern then failed to match, and `search()` returned `[]` — indistinguishable from "no such device". No HTTP-only client can pass that challenge. **Notebookcheck was reachable all along but crippled by our own filter**: it titles canonical device pages `<name> - Reviews and Specs`, and the article filter discarded anything matching `review`, so `Galaxy Z Fold8` and `Z Fold8 Ultra` were dropped while the older bare-titled `Z Fold7` survived — the filter removed precisely the newest devices. Its detail pages also carry a full spec table (Processor/Memory/Display/Storage/Battery/OS/Released) that was never read; only the JSON-LD image was extracted, so RAM, storage, battery, OS and release date never arrived from that source. **PhoneDB** replaces GSMArena for phone coverage, behind a relevance gate: its `filter=`/`model=` parameters are ignored (only the `search_exp` POST searches), and for a model it does not carry it falls back to a loose match returning ~120 unrelated phones. `search()` now returns a `DeviceSearchResponse` with a per-source `DeviceSearchStatus` (`ok`/`blocked`/`unreachable`/`markupChanged`) so a bot-wall, an outage and a changed layout are no longer all reported as "No results found"; a zero-match query stays `ok`, recognised via `isNotebookcheckSearchPage`/`isPhonedbResultsPage`, so the new signal does not cry wolf on every uncarried device. Parsing moved to a network-free `device_search_parsers.dart` covered by fixture-driven tests, `stripHtml` now *decodes* entities instead of deleting them (`12&nbsp;GB` used to collapse to `12GB`), and `tool/check_sources.dart` reports source health in one command. Templates: `device_templates.json` had not been touched since `v0.1.0`, so 19 devices were added (iPhone 17 family, Galaxy S26 family, Z Fold7/Fold8/Fold8 Ultra, Z Flip7, Pixel 10 Pro Fold, Xiaomi 17 Pro/Pro Max, Tab S11 Ultra, M5 MacBooks) with every spec harvested from live sources rather than written from memory. Four template defects fixed: `toDevice` hardcoded `storage.first` so multi-capacity templates always collapsed to the smallest, the 14 VPS templates' object-form `cpu` detail was discarded at parse time and unrecoverable via preset lookup, the picker searched `name` only although its tiles show brand/CPU/RAM, and `validate_json.dart` checked only that files parse — it now checks fields, types, the category enum, duplicates and sort order, which immediately found four previously unknown duplicate preset entries. `PRIVACY_POLICY.md` and the in-app policy page were materially inaccurate independently of this work (they claimed "No other network communication takes place" while the app already contacted GSMArena, Notebookcheck and Startpage) and were corrected in all four languages. Versions unified to `1.4.0+38` / MSIX `1.4.0.0` / installer `1.4.0`.
- `v1.5.0`: The adaptive-layout foundation for foldables, tablets and desktop windows — the first of six releases that bring every screen onto one set of rules, adopted wholesale from the conventions MyAnime worked out in its 1.5.2–1.5.6 releases. **A new policy module, `lib/shared/utils/adaptive_layout.dart`, imports nothing but `dart:core` and holds every width decision the app makes.** Its split rule `canSplitLayout` is an aspect test, not a width breakpoint, and the Galaxy Z Fold 8 is why: it unfolds to a 4:3 *landscape* panel, so in portrait it is 3:4 and narrower relative to its height than the near-square Fold 7 it replaced, and one device needs two answers at one width — width ≥ 600, height ≥ 480 and width/height ≥ 0.82 give it two panes in landscape and the original single column in portrait. No page splits yet; the rule lands first so 1.5.1's lists and 1.5.2's detail pages gate on something already tested. **The shell moves navigation to the side from 600 logical pixels**: a `NavigationRail` (`groupAlignment: 0`, scrollable at compact heights) built from the same destination list as the bottom bar, chosen by `useNavigationRail`, a second, width-only rule kept deliberately apart from the split rule — a phone in landscape at 915 × 412 cannot split but spends a fifth of its height on a bottom bar while 915 dp of width sit idle, and a Z Fold 8 in portrait gets a rail for the same reason. MyAnime's bottom-bar inset was deliberately not ported: MyDevice's tab pages each bring their own `Scaffold` under the shell's, so a page body never sits under the bar, and the device list's `bottom: 80` is clearance for its three floating action buttons. **The three inline breakpoints the app had are gone**, each now a named predicate with its number justified in a doc comment: the services overview's metric grid goes through `serviceMetricColumns`, arithmetically identical to the inline rule so no viewport changed; the topology card's `< 680` becomes `useTopologyActionsRow` at the same 680, but the card is now handed the width left after the rail, so a Pixel 10 Pro Fold in portrait stacks its actions under the title where it used to row them; and the finance summary's `>= 520 ? 3 : 2` becomes `financeSummaryColumns`, a `columnCapacity` at 160 dp floored at two (the card never stacked one metric per row and a cover screen must not start), whose third column arrives at 512 rather than 520. **Both online-search dialogs derive their height from the window** instead of a fixed 560 / 480 that overflowed a phone or a folded cover screen held in landscape: `dialogBodyHeight` leaves 40 above and below, stops at the old sizes where there is room (a Fold 8 in landscape is unchanged) and never drops below 240; width is capped at Material's 560, which also stops the dialog stretching across a tablet. The Android manifest already declared `screenLayout|screenSize|smallestScreenSize|density`, so folding and unfolding resize the window without an activity restart and nothing else was needed. Documented in a new `doc/en-us/adaptive-layout.md` with the device tables and the reasoning, and covered by pure-function tests at every named device geometry plus rendered tests of the shell and the dialogs, driven in Simplified Chinese because `flutter_test`'s default font renders Latin glyphs as full em squares. Versions unified to `1.5.0+39` / MSIX `1.5.0.0` / installer `1.5.0`.
- `v1.5.1`: Lists that use a wide screen. Once a window passes 1.5.0's split rule, the device, network and dataset lists and the services page's devices / routes / ports views fill it with as many columns of a stated minimum width as fit, capped at four, laid out left to right then top to bottom — Google's adaptive-minimum-width feed guidance through `columnCapacity`, never a hardcoded count per breakpoint. **Each tile brings its own minimum, justified in its doc comment**: 320 dp for a device card (152 of avatar, gap and trailing chrome leaves 168 for a twenty-character name and a two-line subtitle), 300 for a network card (a single-line "type · subnet" subtitle), 320 for a dataset tile (four storage lines that must not wrap) and 320 for the services cards. The minimums are what make one width answer differently per list: a tablet in landscape gives networks three columns where the others get two, and a Z Fold 7 in portrait leaves the device list three logical pixels short of a second column while the dataset list beside it gets one — the rule working at its boundary. `listColumnCount` takes the minimum as a parameter, the one departure from MyAnime's version, because MyDevice has four tile shapes. **Each list remembers its own count** in `storage_config.json` (`deviceListColumns`, `networkListColumns`, `dataSetListColumns`, `serviceListColumns`), device-locally because window size is a property of the device and not of the account, defaulting to auto — removed from the file, not written as zero — and clamped rather than rewritten when the window shrinks, so a count set on a desktop survives a fold and comes back on unfolding; the app-bar control is hidden, not disabled, wherever the width fits only one column, and in reorder mode and on the services overview, which is a heterogeneous scroll and deliberately stays single-column. Content width is `shellContentWidth` less each page's own padding, so the rail is paid for. **Gestures follow the columns**: the device and dataset tiles keep swipe-to-edit and swipe-to-delete at one column and drop them above it, because a horizontal drag inside one narrow cell is ambiguous; the trailing chevron becomes a menu carrying the same actions — the menu the services tiles already had — and since delete has no other entrance on either page, that menu is what keeps it reachable. Rows are `Row`s of `Expanded` cells rather than a `GridView`, so the device list keeps `ListView.builder` virtualization and the services views keep their cards as children of one scroll view; short final rows are padded so the remaining tiles keep their width. Covered by pure-function tests at every named device, a preference round-trip test, and rendered tests of all four lists against a seeded storage directory at a Z Fold 8 both ways, a Pixel 9 both ways and a tablet, with the shared test helpers extracted to `test/support/`. Versions unified to `1.5.1+40` / MSIX `1.5.1.0` / installer `1.5.1`.
- `v1.5.2`: Detail pages that use a wide screen, and a finance overview whose numbers sit beside its chart. **The device and network detail pages split into two panes** on any window the app-wide rule admits, through `useDetailTwoPane`, a one-line delegate in the new `lib/shared/utils/detail_layout.dart` that the tests assert still agrees with `canSplitLayout` at every named viewport; the left pane is `detailLeftPaneWidth`, proportional (0.36 of the window) and clamped to 260–420 because one foldable generation spans ~672 to ~954 dp unfolded. The device page keeps its header card, location map and notes on the left and scrolls the spec cards on the right, with a third gate the network page does not need: a device with no spec section at all keeps the single column, because every section is conditional and the right pane would otherwise be blank, whereas an empty assignment list already renders an empty-state card. The single-column order is untouched. Both pages are pushed above the shell, so they measure the raw window and subtract no rail. **The finance overview's three summary metrics move beside the asset-distribution pie** under a double gate — `canSplitLayout` on the screen and `useFinanceSideBySide` on the body width (a 240 dp metric column plus a 340 dp chart plus the gap) — and a third condition, that the distribution has data, since an empty chart renders a one-line placeholder that would strand the metrics beside a blank half. `financeSummaryPaneWidth` is 0.34 of the width clamped to 240–360 with no right-hand cap, because none can bind: the chart grows at 0.66 and meets its floor exactly at the gate, an invariant a loop test pins across the whole range. Unlike MyAnime's statistics page every unfolded foldable clears the floor, since MyDevice's two blocks are smaller — the rule working, not slack in it — and the row sits in an `IntrinsicHeight` so both cards stretch to the chart's height. A phone in landscape keeps the stacked layout by the same deliberate choice the split rule makes everywhere; that cost is written down. Covered by the pure-function tests and by rendered tests of all three pages at a Z Fold 8 both ways, a Z Fold 7 in portrait, a phone both ways, a tablet and the 600 × 480 floor. Versions unified to `1.5.2+41` / MSIX `1.5.2.0` / installer `1.5.2`.
- `v1.5.3`: The device edit page brought onto the shared layout rule. On any window `useDetailTwoPane` admits — the same delegate the detail pages use — the form splits into two panes inside the one `Form`: the avatar picker, the name field and the category dropdown fixed on the left, everything from brand down scrolling on the right. **The left pane is non-scrolling by construction.** A fixed large avatar would not fit the 424 dp a pane has at the 480 dp minimum split height, so the new `editAvatarSize` takes the height left after `deviceEditLeftPaneFieldBudget` (318: padding, three worst-case rows of chips, two 56 dp fields, their gaps and 22 of slack for a validation error) and clamps it to 56–160, and the pure test loops every window height from 480 to 1200 asserting the column fits; at the floor the avatar is 106, on a Z Fold 8 in landscape 160. The pane still sits in a `SingleChildScrollView` with its minimum height pinned, so a soft keyboard degrades it to a scroll rather than an overflow, and the rendered test pins that under a 300 dp inset. **Brand, model and serial stay on the right, deliberately**: brand's `Autocomplete` overlay is hard-capped at 360 dp, wider than a 260 dp pane, and its 68 dp would push the avatar under its 56 dp floor at the split minimum. The single-column order is untouched — the fields were extracted into `_buildFields`, `_buildNameField` and `_buildCategoryField` so the two layouts share them rather than duplicate them — and every controller already lived in `State`, so a half-typed value survives folding mid-edit. Versions unified to `1.5.3+42` / MSIX `1.5.3.0` / installer `1.5.3`.
